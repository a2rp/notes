# 09 - Pseudo-elements: Example

## Goal

Style decorative generated content, text fragments, list markers, selected text, placeholder text, and a file input button with pseudo-elements.

## Complete example

Copy the complete document into a file named `index.html`, then open it in a browser. Select some text and try the form controls to see the browser-rendered parts.

```html
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Pseudo-element Examples</title>
  <style>
    * {
      box-sizing: border-box;
    }

    body {
      margin: 0;
      padding: 2rem;
      background-color: #f1f5f9;
      color: #1e293b;
      font-family: Arial, sans-serif;
    }

      padding: 1.5rem;
      background-color: white;
      border: 1px solid #cbd5e1;
      border-radius: 0.75rem;
    }

    h1,
    h2 {
      color: #173b68;
    }

    p,
    label,
    li {
      line-height: 1.7;
    }
```

## Expected output

The page displays a centered white panel containing a blue notice, a reading note, an ordered list, a search field, and a file picker.

- The notice begins with a small blue `TIP` badge and ends with a green check mark. Both are generated by pseudo-elements and are decorative.
- The reading note has a large purple first letter. Its first currently formatted line is bold and slate-colored.
- The ordered-list numbers are purple and bold. The final marker is replaced with a green check mark.
- Selecting text changes its text and background colors.
- The search hint is slate-colored while it is shown. The search input still has a separate visible label.
- The file input's button is blue with bold white text. Its file-selection behavior remains the browser's native behavior.

## How each pseudo-element works

### Generated content before and after an element

```css
.notice::before {
  content: "TIP";
  /* decorative badge styles */
}

.notice::after {
  content: " ✓";
  /* decorative check mark styles */
}
```

The originating element is the paragraph with class `notice`. `::before` renders the badge before the paragraph's original text, and `::after` renders the check after it. Neither string is added to the HTML source.

### First letter and first line

```css
.article-copy::first-letter { ... }
.article-copy::first-line { ... }
```

`::first-letter` styles the first typographic letter. `::first-line` styles whichever text currently fits on the first formatted line. Resize the browser to see the first line reflow.

### List markers

```css
.steps li::marker { ... }
.steps li:last-child::marker { ... }
```

`::marker` styles the number marker of each ordered-list item. The second rule changes the final item's marker to a check. The HTML remains a real ordered list.

### Selected text

```css
::selection {
  color: white;
  background-color: #4338ca;
}
```

Select text on the page to see the selection colors. Only a defined subset of properties applies to `::selection`, so keep the selected text easy to read.

### Placeholder and file selector button

```css
input[type="search"]::placeholder { ... }
input[type="file"]::file-selector-button { ... }
```

The first selector styles the search hint. The second styles only the button portion of the file input. Both controls remain real HTML form controls with their native behavior.

## Try these changes

1. Change the notice's `::before` content to `"INFO"` and see the generated badge text change.
2. Change `content: " ✓"` to `content: ""`. The green check mark disappears, while the pseudo-element has no visible content.
3. Remove the `::first-letter` rule and compare the paragraph.
4. Resize the browser and watch where the bold first line ends.
5. Remove the custom `content` from `.steps li:last-child::marker`. The final list item returns to its normal ordered-list number.
6. Select different text to see the `::selection` styling.
7. Type into the search field. The placeholder styling disappears as the hint is no longer shown.
8. Choose a file and observe that the button's appearance is customized while its native function remains.
9. Inspect the HTML source. The `TIP` badge and check mark are CSS-generated, not HTML elements.

## Key points

- Pseudo-elements use two colons and style parts of rendered content.
- `::before` and `::after` use `content` to generate their presentation.
- `::first-letter` and `::first-line` style typographic portions of text.
- `::marker` styles a list marker without replacing semantic list markup.
- `::selection`, `::placeholder`, and `::file-selector-button` style specific browser-rendered parts.
- Generated content is decorative in this example. Important content and labels remain in HTML.
- Pseudo-elements change presentation, not the document source or control behavior.
