# 84 - Package.json, npm, dependencies, scripts, and package managers example

This example builds a small Node.js project to show how **package.json**, npm scripts, a development dependency, **package-lock.json**, and **node_modules** fit together. The project prints a startup message, checks its own manifest, and provides a local command-line banner.

## Goal

Create a project that a teammate can install from its manifest and lockfile, then run with named npm scripts.

## Project files

Create this structure:

~~~text
reading-list-demo/
  .gitignore
  package.json
  src/
    index.cjs
  test/
    smoke-test.cjs
~~~

The **package-lock.json** file will be generated by npm after installing the development dependency. Do not write it by hand.

## 1. Create the project manifest

Save this as **package.json**:

~~~json
{
  "name": "reading-list-demo",
  "version": "1.0.0",
  "private": true,
  "description": "A small project for practicing npm package management",
  "scripts": {
    "start": "node src/index.cjs",
    "test": "node test/smoke-test.cjs",
    "banner": "cowsay \"Package setup is ready\""
  },
  "devDependencies": {
    "cowsay": "^1.6.0"
  }
}
~~~

This is a private application, so **private** is **true**. It has no runtime package dependency. **cowsay** is a development dependency used only by the optional **banner** script. The **start** and **test** entries give the project repeatable commands.

## 2. Ignore installed packages

Save this as **.gitignore**:

~~~gitignore
node_modules/
~~~

npm generates **node_modules** from the manifest and lockfile. Keep the generated directory out of version control.

## 3. Create the application entry file

Save this as **src/index.cjs**:

~~~js
console.log('Reading list project is ready.');
console.log('The start command came from package.json.');
~~~

This small entry file uses only a built-in output function, so the application itself needs no installed runtime package.

## 4. Create a smoke check

Save this as **test/smoke-test.cjs**:

~~~js
const assert = require('node:assert/strict');
const fs = require('node:fs');
const project = require('../package.json');

assert.equal(project.name, 'reading-list-demo');
assert.equal(project.private, true);
assert.equal(project.scripts.start, 'node src/index.cjs');
assert.equal(project.devDependencies.cowsay, '^1.6.0');
assert.equal(fs.existsSync('src/index.cjs'), true);

console.log('Manifest and entry file checks passed.');
~~~

The check uses Node.js built-in modules, so it does not need a separate test-runner package. It verifies that the manifest has the expected project settings and that the entry file exists. npm runs this script from the package root.

## 5. Install and create the lockfile

Open a terminal in the **reading-list-demo** folder and run:

~~~sh
npm install
~~~

npm installs **cowsay** and creates **package-lock.json**. The lockfile records the concrete dependency tree selected for this project. Commit it together with **package.json**. The install output can vary, so the exact number of packages and timing are not part of the expected result.

The folder now contains:

~~~text
reading-list-demo/
  .gitignore
  package-lock.json
  package.json
  node_modules/
  src/
    index.cjs
  test/
    smoke-test.cjs
~~~

**node_modules** is installed locally but ignored by Git. **package-lock.json** is tracked so another install can reproduce the selected dependency tree.

## 6. Run the project scripts

Run the application:

~~~sh
npm start
~~~

Expected output:

~~~text
Reading list project is ready.
The start command came from package.json.
~~~

Run the smoke check:

~~~sh
npm test
~~~

Expected output:

~~~text
Manifest and entry file checks passed.
~~~

Run the development tool:

~~~sh
npm run banner
~~~

The local **cowsay** executable prints an ASCII speech bubble with the message **Package setup is ready**. npm makes the project's locally installed executable available to the script, so this command does not require a global **cowsay** installation.

## 7. Reproduce the install from the lockfile

To see the clean-install workflow, remove the generated **node_modules** directory, then run:

~~~sh
npm ci
~~~

npm installs the dependency tree described by **package-lock.json**. It does not change **package.json** or the lockfile. Run **npm test** and **npm run banner** again to confirm that the project tools were restored.

In a real repository, do not delete **node_modules** just for this demonstration. The important point is that another checkout can create its own installed packages from the committed manifest and lockfile.

## What each file does

| File or directory | Purpose |
| --- | --- |
| **package.json** | Describes the project, the development dependency, and the npm scripts |
| **package-lock.json** | Records npm's concrete dependency resolution |
| **node_modules/** | Holds packages installed on this machine; normally ignored by Git |
| **src/index.cjs** | The application entry file called by the start script |
| **test/smoke-test.cjs** | A small check called by the test script |
| **.gitignore** | Keeps generated installed packages out of version control |

## Make a runtime dependency change

If the application later imports an external library while it runs, add it as a runtime dependency from the project root:

~~~sh
npm install package-name
~~~

npm will add it to **dependencies** and update the lockfile. Replace **package-name** with an actual package and update the application to use it. Keep development-only tools, such as **cowsay** in this example, in **devDependencies**.

After adding or removing a package, inspect the changes with:

~~~sh
git status --short
git diff -- package.json package-lock.json
~~~

The manifest and lockfile should describe the same intended dependency change. Do not add **node_modules** to Git.

## Try it yourself

1. Add a **check** script that prints a short project status message.
2. Change the **banner** command text and run **npm run banner** again.
3. Run **npm run** to see the project's named scripts.
4. Remove **node_modules** and run **npm ci** to restore the local tool.
5. Add a runtime dependency with **npm install package-name**, then compare **dependencies** with **devDependencies** in the manifest.
6. Run **git status --short** and confirm that the lockfile is listed while **node_modules/** is ignored.
7. Change the manifest's cowsay range without updating the lockfile, then run **npm ci** and observe the consistency error. Restore the original manifest and lockfile after the experiment.

## Key points

- **package.json** describes the project and provides named npm scripts.
- **dependencies** are for packages needed at runtime; **devDependencies** are for development tools.
- **npm install** installs packages and generates or updates **package-lock.json**.
- **npm ci** performs a clean install from a consistent lockfile.
- Commit the manifest and lockfile together, but normally ignore **node_modules/**.
- npm scripts can use locally installed executables without a global installation.
